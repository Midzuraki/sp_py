**Этап 0. Скрипт-антипаттерн (без ИИ).** Создал `BadBank.py` с глобальными `balance` и `history`, функциями `deposit(amount)` и `withdraw(amount)`. Сумма не проверяется, при нехватке средств выводится сообщение и вызывается `sys.exit()`, логирования нет, исполнение линейное.

```python
"""ЛР1, этап 0: скрипт-антипаттерн (писался без ИИ).

Намеренно плохой код: глобальные переменные, нет проверки суммы,
нет логирования, при ошибке программа падает через exit().
"""
import sys

balance = 0
history = []


def deposit(amount):
    global balance
    # Нет проверки, что сумма положительная (можно внести -500!)
    balance += amount
    history.append(f"Пополнение: +{amount} руб.")
    print(f"Внесено {amount} руб.")


def withdraw(amount):
    global balance
    if amount > balance:
        print(f"Попытка снять {amount} руб...")
        print("ОШИБКА! Недостаточно средств. Программа завершена.")
        sys.exit()  # при любой ошибке скрипт просто падает
    balance -= amount
    history.append(f"Снятие: -{amount} руб.")
    print(f"Снято {amount} руб.")


# Линейный запуск: 3-4 операции и завершение
print("Скрипт запущен...")
deposit(1000)
withdraw(200)
withdraw(900)
print("До этой строки программа не дойдёт")
```

**Этап 5. Рефакторинг.** По итогам ревью ИИ и собственного анализа внёс 4 улучшения (раздел 4). Итоговый код класса:

```python
"""ЛР1: класс BankAccount с инкапсуляцией (первая рабочая версия + рефакторинг)."""


class BankAccount:
    bank_name = "Центральный Банк"  # атрибут класса: общий для всех счетов

    def __init__(self, owner: str, initial_balance: float = 0.0) -> None:
        if initial_balance < 0:
            raise ValueError("Начальный баланс не может быть отрицательным")
        self.owner = owner
        self._balance = float(initial_balance)  # приватный атрибут экземпляра
        self._transactions: list = []  # история операций

    def _add_transaction(self, operation_type: str, amount: float) -> None:
        """Приватный метод: историю пишет только сам класс."""
        self._transactions.append(
            {
                "type": operation_type,
                "amount": amount,
                "balance_after": self._balance,
            }
        )

    def deposit(self, amount: float) -> None:
        """Пополнение счета: сумма должна быть строго положительной."""
        if amount <= 0:
            raise ValueError("Сумма пополнения должна быть положительной")
        self._balance += amount
        self._add_transaction("Пополнение", amount)

    def withdraw(self, amount: float) -> None:
        """Снятие: нельзя снять неположительную сумму или уйти в минус."""
        if amount <= 0:
            raise ValueError("Сумма снятия должна быть положительной")
        if amount > self._balance:
            raise ValueError(
                f"Недостаточно средств для снятия {amount:g} руб. "
                f"(доступно: {self._balance:g})"
            )
        self._balance -= amount
        self._add_transaction("Снятие", amount)

    def get_balance(self) -> float:
        """Геттер баланса (читать _balance напрямую не нужно)."""
        return self._balance

    def get_transactions(self) -> list:
        """Геттер возвращает КОПИЮ истории, чтобы её нельзя было испортить извне."""
        return self._transactions.copy()

    def __str__(self) -> str:
        return f"Счет {self.owner}: {self._balance:g} руб. ({self.bank_name})"
```

## Раздел 5. Ответы на контрольные вопросы

**Почему `_balance` приватный?**
Баланс — это состояние, которое должно подчиняться правилам (сумма положительная, в минус не уйти). Если атрибут публичный, любой код может написать `account.balance = -1000000`, обойдя все проверки. Приватный `_balance` (по соглашению Python — префикс подчёркивания) показывает: «снаружи не трогать, работай через методы». Это и есть инкапсуляция — данные и правила работы с ними живут в одном месте.

**Зачем нужен геттер `get_balance()`, если можно просто читать `_balance`?**
Геттер — публичный контракт класса. Внутреннее хранение может измениться (баланс в копейках, подсчёт по истории операций, блокировка на время операции), а вызывающий код продолжит работать без изменений. Кроме того, чтение через метод/свойство не даёт случайно присвоить значение. Прямое чтение `_balance` привязывает внешний код к внутренней реализации.

**Почему `_add_transaction` приватный? Кто должен его вызывать?**
Историю должен писать только сам класс, и только в момент реальной операции (внутри успешных `deposit` и `withdraw`). Если бы метод был публичным, любой код мог бы дописать в историю несуществующую операцию, и история перестала бы соответствовать балансу. Вызывают его только методы самого `BankAccount`.
