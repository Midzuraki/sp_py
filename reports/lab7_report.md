**Проблема `.gitignore` и папки `data/`.** Проверил настоящим `git`: с правилами `data/` + `!data/.gitkeep` в репозиторий попадает только `.gitignore`, а с правилами `data/*` + `!data/.gitkeep` — ещё и `data/.gitkeep`:

```text
### ЛР7: .gitignore 'data/' vs 'data/*' (настоящий git)
.gitignore: 'data/' + '!data/.gitkeep' -> в Git попали: ['.gitignore']
.gitignore: 'data/*' + '!data/.gitkeep' -> в Git попали: ['.gitignore', 'data/.gitkeep']
```

Причина: запись `data/` исключает папку целиком, Git в неё даже не заходит, и исключение для файла внутри не срабатывает; `data/*` исключает только содержимое.

## Раздел 5. Ответы на контрольные вопросы

В тексте ЛР7 нет отдельного списка контрольных вопросов, но в нём есть вопросы-подсказки; ниже ответы на них и на обязательное «обоснование структуры».

**Почему принято разделять `src/` и `tests/`, а данные выносить в отдельную папку?**
Код и тесты разделяют, чтобы тесты не попадали в пакет, а импорты в них выглядели как у пользователя библиотеки (проверяется установленный пакет, а не случайные файлы рядом). Данные (`books.json`, `notes.txt`, `stats.csv`) — это результат работы программы: они уникальны для каждого пользователя и постоянно меняются, поэтому лежат отдельно (`data/`), не коммитятся и не смешиваются с исходниками; пути к ним передаются параметрами, и тесты работают с временными копиями.

**Как сохранить пустую папку `data/` в Git, если её содержимое в `.gitignore`?**
Использовать `data/*` (игнорировать содержимое, а не папку) и добавить исключение `!data/.gitkeep` с пустым файлом-заглушкой. Запись `data/` не подходит: Git не заходит в игнорируемую папку, и исключение не сработает.

**Почему `Library` не работает с файлами напрямую?**
Разделение «что делать» и «как хранить»: `Library` отвечает за правила (поиск, удаление, суммы), `storage` — за формат и расположение файлов. Хранилище можно заменить (например, SQLite) без изменений в `Library`, а оба слоя тестировать независимо.

**Зачем функциям `storage` принимать путь параметром?**
Это позволяет тестам использовать временные файлы (`tmp_path`) и не затрагивать рабочие данные; в самих функциях нет зашитых путей и скрытых зависимостей.

**Почему `pytest` вынесен в `optional-dependencies`?**
Он нужен только разработчикам; пользователю приложения достаточно `pip install .`, а разработчику — `pip install -e ".[dev]"` одной командой.
