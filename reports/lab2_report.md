## Раздел 5. Ответы на контрольные вопросы

**Вопросы для рефлексии**

1. *Назначение `__str__` и `__repr__`, различие.* `__str__` — «красивая» строка для пользователя (`print(obj)`, `str(obj)`, f-строки). `__repr__` — однозначное техническое представление для разработчика (REPL, логи, сообщения об ошибках), по возможности такое, чтобы по нему можно было воссоздать объект. Если `__str__` не определён, Python использует `__repr__`; обратного нет.
2. *Почему `__init__.py` обязателен в `src/`, а в `scripts/` — нет?* `src/` — пакет: из него импортируют, и `__init__.py` явно помечает папку как пакет (нужно setuptools при сборке и `pip install -e .`, pytest, mypy). `scripts/` — набор запускаемых файлов, их не импортируют, поэтому пакетной структуры не требуется (хотя `python -m scripts.demo` работает и так — благодаря пакетам-пространствам имён).
3. *Почему структуру нужно создавать заранее?* Она определяет, где что лежит и как всё импортируется. Если делать её «по ходу», приходится переносить файлы и переписывать импорты, код и тесты смешиваются, настройка инструментов (pytest, mypy, CI) усложняется. Заранее заданная структура масштабируется и понятна другим разработчикам.

**Вопросы по исключениям**

4. *Зачем базовое исключение `BankAccountError`?* Это общий предок всех ошибок домена: одним `except BankAccountError` можно поймать любую из них, не перехватывая посторонние исключения.
5. *Почему все исключения наследуются от одного класса?* Иерархия позволяет выбирать уровень обработки: ловить конкретную (`InsufficientFundsError`) или всё семейство; ошибки домена отделены от системных; общий тип удобен в аннотациях и документации.
6. *Что будет без собственных исключений?* Пришлось бы использовать `ValueError`/`Exception`; по ним нельзя отличить разные бизнес-ошибки, а широкий `except Exception` скрывал бы реальные баги (опечатки, `KeyError`).

**Вопросы по импорту**

7. *Почему Python не видит `src`, хотя папка есть?* Модули ищутся в `sys.path`. При запуске `python scripts/seed_accounts.py` туда попадает папка скрипта (`scripts/`), а не корень проекта, где лежит `src/`.
8. *Где Python ищет модули по умолчанию?* В `sys.path`: папка запущенного скрипта (или текущая при `-m`), каталоги из `PYTHONPATH`, стандартная библиотека, `site-packages` окружения.
9. *Что сделать, чтобы Python «узнал» о проекте?* Установить проект в окружение: `pip install -e .` (альтернативы — `PYTHONPATH` или запуск через `python -m` из корня).

**Вопросы про `pip install -e .`**

10. *Что означает `-e`?* `--editable`: проект ставится «по ссылке» на исходную папку, а не копируется в `site-packages`.
11. *Чем удобно для разработки?* Правки в коде действуют сразу, без переустановки; тесты и скрипты всегда работают с актуальным кодом.
12. *Что означает точка?* Текущую папку: pip берёт `pyproject.toml` из неё и по нему устанавливает проект.
13. *Что будет, если переместить папку проекта?* Ссылка в окружении указывает на старый путь и перестаёт работать (`ModuleNotFoundError`); нужно заново выполнить `pip install -e .` из нового места.
