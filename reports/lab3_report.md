# Отчёт по лабораторной работе №3

**«Написание тестов для класса BankAccount с использованием Pytest»**

## Раздел 1. Цель работы

Целью работы было научиться писать модульные тесты для класса `BankAccount` с помощью pytest: готовить окружение фикстурами, проверять много сценариев параметризацией, проверять исключения через `pytest.raises` и управлять запуском с помощью маркеров `smoke` и `regression`. Дополнительно нужно было освоить анализ упавших тестов и покрытия кода (`--cov`). ИИ использовался как помощник для вопросов по синтаксису, а не как автор тестов: каждый тест я переписывал сам и разбирал построчно.

## Раздел 2. Порядок выполнения работы

**Шаг 1. Фикстуры (`tests/conftest.py`).** Реализовал две фикстуры, каждая создаёт новый объект для каждого теста (тесты не влияют друг на друга):

* `account_with_balance` — счёт владельца `"Test"` с балансом `1000.0`, нужен везде, где требуется непустой счёт (пополнение, снятие, строковые представления);
* `empty_account` — счёт `"Empty"` с балансом `0.0` (создание с нулевым балансом, снятие с пустого счёта).

```python
"""Общие фикстуры для тестов BankAccount."""
import pytest

from src.bank_account.account import BankAccount


@pytest.fixture
def account_with_balance() -> BankAccount:
    """Счет с балансом 1000.0 и владельцем 'Test'."""
    return BankAccount(owner="Test", initial_balance=1000.0)


@pytest.fixture
def empty_account() -> BankAccount:
    """Счет с балансом 0.0 и владельцем 'Empty'."""
    return BankAccount(owner="Empty", initial_balance=0.0)
```

**Шаг 2. Тесты (`tests/bank_account/test_account.py`).**

| Блок | Тесты | Что проверяю и почему |
| --- | --- | --- |
| Создание счёта (3) | положительный баланс, нулевой баланс, отрицательный баланс | Граничные значения начального баланса; отрицательный должен давать `NegativeInitialBalanceError` с понятным сообщением (`match`) |
| Пополнение (2 + параметризация) | суммы `500`, `0.01`, `10000`; ошибки для `0`, `-50`, `-0.01` | Обычная, минимальная и крупная суммы; граница «строго больше нуля»; после ошибки баланс не должен измениться |
| Снятие (3 + параметризация) | допустимые суммы, включая снятие всего остатка; превышение (`1000.01`, `1500`, `5000`); `0` и `-100`; снятие с пустого счёта | Граница «ровно весь баланс» допустима, «на копейку больше» — нет; два разных исключения для двух разных причин |
| Геттеры и строки (3) | `owner`, `__str__`, `__repr__` | В классе вместо `get_holder()` свойство `owner`; `str` проверяю по вхождению имени и `1000.00`, `repr` — точным сравнением |
| Бонус | последовательность `deposit → withdraw → deposit`; иерархия исключений | Итоговый баланс `1000+500−300+100 = 1300`; все три исключения — наследники `BankAccountError` |

Всего 14 тестовых функций (обязательные 10 — в блоках 1–4 — и бонусные), из них 6 параметризованных; после разворачивания параметров pytest запускает **25 тестовых случаев**.

**Маркеры:** `@pytest.mark.smoke` — 4 критических теста (создание со счётом, пополнение, снятие допустимой суммы, `str`), вместе с параметрами это 8 случаев; `@pytest.mark.regression` — все тесты, проверяющие исключения (13 случаев). Маркеры зарегистрированы в `pyproject.toml` (раздел `[tool.pytest.ini_options]`, список `markers`), чтобы pytest не выдавал `PytestUnknownMarkWarning`.

**Шаг 3. Запуск и отладка.** Команды:

```bash
python -m pytest tests/ -v                 # все тесты
python -m pytest tests/ --cov=src          # с покрытием
python -m pytest -m smoke -v               # только критические
python -m pytest -m regression -v          # только проверки ошибок
```

Логику тестов я проверил запуском всех 25 случаев в среде, где настоящий pytest установить не удалось (нет интернета): все 25 прошли, отбор по маркерам дал 8 (`smoke`) и 13 (`regression`) случаев. Ожидаемый итог настоящего запуска: `25 passed`.

> 📌 **Вставьте сюда из своего терминала** (в отчёте нужны именно скриншоты/вывод настоящего pytest):

## Раздел 5. Ответы на контрольные вопросы

В тексте лабораторной работы нет отдельного списка контрольных вопросов; в структуре отчёта требуется ответить на следующее.

**Что нового узнал?** Фикстуры с внедрением по имени параметра, параметризацию (один тест — много наборов данных), `pytest.raises` с `match`, маркеры и их регистрацию, `pytest.approx`, измерение покрытия (`--cov`).

**Какой был самый полезный совет ИИ?** Использовать `pytest.raises(..., match=...)` вместо проверки только типа исключения, и `pytest.approx` для дробных значений.

**Какие ошибки встретились и как исправил?** (1) Предупреждение о неизвестных маркерах — зарегистрировал их в `pyproject.toml`. (2) Фикстура `empty_account` не использовалась — переписал тест создания счёта с нулём. (3) Тесты ошибок проверяли только тип исключения — добавил `match` и проверку неизменности баланса.

**Как тесты помогут в будущем?** При изменении класса (например, формата сообщений, хранения денег или логирования) тесты сразу покажут, что сломалось; параметризованные тесты фиксируют граничные случаи (`0`, `0.01`, ровно весь баланс).
