# Личная библиотека 📚 (ЛР7)

Консольное приложение для учёта домашней библиотеки. Три формата хранения:
**JSON** (каталог книг), **TXT** (заметки и рецензии), **CSV** (статистика чтения по месяцам).
Покрыто автотестами на **pytest**.

## Структура проекта

```
lab7_library/
├── .gitignore               # что не попадает в Git (venv, кеши, рабочие данные)
├── pyproject.toml           # метаданные, зависимости, сборка, настройки pytest, команда `library`
├── README.md                # этот файл: структура, обоснование, запуск
├── main.py                  # точка входа: только вызывает run()
├── src/
│   └── library_app/         # весь исходный код приложения
│       ├── __init__.py      # делает папку пакетом
│       ├── models.py        # модель данных: класс Book
│       ├── storage.py       # работа с файлами JSON/TXT/CSV (только функции, пути - параметрами)
│       ├── library.py       # бизнес-логика: класс Library (файлов не касается)
│       └── cli.py           # консольное меню и ввод/вывод
├── data/                    # рабочие данные пользователя (books.json, notes.txt, stats.csv)
│   └── .gitkeep             # заглушка: Git хранит пустую папку, сами данные игнорируются
└── tests/
    ├── conftest.py          # общие фикстуры (tmp_path, библиотеки, пример книги)
    ├── test_models.py       # тесты Book
    ├── test_storage.py      # тесты JSON/TXT/CSV
    └── test_library.py      # тесты Library
```

## Обоснование структуры

* **`src/` отдельно от `tests/`.** Код приложения и проверки живут раздельно: тесты не попадают
  в установленный пакет, а импорты в тестах идут так же, как у настоящего пользователя пакета
  (`from library_app.library import Library`). Вариант `src/`-layout ещё и не даёт случайно
  импортировать код «из текущей папки» вместо установленного пакета.
* **`data/` отдельно от кода.** Данные — это результат работы программы, а не исходники. Они
  меняются при каждом запуске, у каждого пользователя свои, поэтому их не коммитят
  (`data/*` в `.gitignore`), а код можно обновлять, не боясь стереть чьи-то книги.
* **Папка `data/` остаётся в репозитории через `.gitkeep`.** Git не хранит пустые папки. Если
  написать в `.gitignore` просто `data/`, Git проигнорирует папку целиком, и исключение уже не
  сработает. Поэтому пишем `data/*` (игнорировать содержимое) и `!data/.gitkeep` (но этот файл —
  оставить). Тогда после `git clone` папка существует, и приложение сразу работает.
* **Три слоя: модель / хранилище / логика / интерфейс.** `Book` ничего не знает о файлах,
  `storage` — только функции «данные → файл» и «файл → данные», `Library` решает «что делать» и
  вызывает `storage` («как хранить»), `cli` отвечает только за ввод-вывод. Любой слой можно
  заменить или протестировать отдельно (например, файлы на SQLite или меню на GUI).
* **Пути приходят параметрами.** Ни одна функция `storage` не знает про `data/`; тесты подставляют
  временную папку `tmp_path` и не трогают рабочие данные.
* **`main.py` — тонкая точка входа**, а ещё есть консольная команда `library`
  (`[project.scripts]` в `pyproject.toml`), которая появляется после установки.

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"            # приложение в режиме редактирования + pytest
python main.py                     # или просто: library
python -m pytest -v                # все тесты
```

Папку с данными можно переопределить переменной окружения `LIBRARY_DATA_DIR`.

## Форматы файлов

| Файл | Формат | Пример строки |
| --- | --- | --- |
| `data/books.json` | JSON, `ensure_ascii=False`, `indent=2` | `{"title": "Война и мир", "author": "Толстой", ...}` |
| `data/notes.txt` | TXT, одна заметка = одна строка | `[2026-11-12 14:30] «Война и мир»: текст заметки` |
| `data/stats.csv` | CSV с заголовком | `2026-11,3,900` (`month,books_read,pages_read`) |
