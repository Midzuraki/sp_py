# Программный комплекс «Центральный Банк Кириешек» (ЦБ Кириешек)

Настоящая техническая документация описывает структуру, порядок развертывания и правила эксплуатации программного обеспечения для управления распределенными хрустящими активами. Проект реализует системный подход к проектированию (ООП) взамен скриптовых антипаттернов.

## 1. Спецификация структуры проекта

Архитектура системы организована в соответствии со стандартом построения масштабируемых Python-приложений:

```text
bank_account_project/
├── .venv/                         # Изолированное виртуальное окружение системы
├── .gitignore                     # Директивы исключения служебных файлов из Git
├── README.md                      # Настоящая техническая документация
├── pyproject.toml                 # Глобальная конфигурация инструментов качества
├── main.py                        # Главная точка входа (Интерфейс оператора ЦБ)
│
├── src/                           # Исходный код (Ядро финансовой системы)
│   ├── __init__.py
│   ├── bank_account/
│   │   ├── __init__.py
│   │   ├── account.py             # Бизнес-логика банковского счета регулятора
│   │   ├── exceptions.py          # Кастомные исключения (Реестр финансовых нарушений)
│   │   └── storage.py             # Номенклатура хранения NoSQL (JSON-сейф)
│   └── core/
│       └── __init__.py
│
├── tests/                         # Модули автоматизированного контроля качества
│   ├── __init__.py
│   ├── conftest.py                # Тестовые фикстуры (Предустановленные счета)
│   └── bank_account/
│       ├── __init__.py
│       └── test_account.py        # Набор модульных тестов верификации класса
│
├── scripts/                       # Вспомогательные утилиты обслуживания
│   ├── demo.py
│   └── seed_accounts.py          # Скрипт первоначального наполнения базы данных
│
└── logs/                          # Архив подотчетной документации
    └── app.log                    # Журнал транзакций с посекундными метками времени
```

## 2. Развертывание банковского узла

Для подготовки программного комплекса к эксплуатации необходимо выполнить следующие процедуры в терминале из корневой директории проекта:

1. **Инициализация и активация изолированной среды:**
   * **Для ОС Windows:**
     ```bash
     python -m venv .venv
     .venv\Scripts\activate
     ```
   * **Для ОС Linux / macOS:**
     ```bash
     python -m venv .venv
     source .venv/bin/activate
     ```

2. **Привязка исходного кода ядра (Editable режим):**
   Команда связывает директорию `src` с виртуальным окружением для корректного разрешения абсолютных импортов модулей:
   ```bash
   pip install -e .
   ```

3. **Установка пакетов верификации кода и тестирования:**
   ```bash
   pip install pytest pytest-cov black isort mypy
   ```

## 3. Инструкция по запуску компонентов

Запуск исполняемых файлов производится строго из корневого каталога проекта с использованием флага модульного исполнения `-m`.

* **Запуск интерактивного терминала оператора ЦБ:**
  ```bash
  python -m main
  ```
  *Интерфейс оснащен сквозной проверкой входящих параметров («Защита от некорректного ввода»). При передаче невалидных данных (символы, пустые строки, отрицательный объем сухариков) система изолирует ошибку, выводит уведомление оператору и продолжает работу.*

* **Запуск генератора демонстрационной базы держателей активов:**
  ```bash
  python -m scripts.seed_accounts
  ```
  *Исполняет пакетную инициализацию шести тестовых счетов (Alice, Bob и др.) и демонстрирует поведение системы при штатных операциях и критическом овердрафте.*

## 4. Протокол верификации системы (Тестирование)

Проверка отказоустойчивости ядра осуществляется посредством фреймворка `pytest`.

* **Проведение полного аудита системы (10+ тестов):**
  ```bash
  python -m pytest tests/ -v
  ```
* **Запуск экспресс-проверки критически важных узлов (Smoke-тесты):**
  ```bash
  python -m pytest -m smoke -v
  ```
* **Анализ покрытия бизнес-логики тестами:**
  ```bash
  python -m pytest tests/ --cov=src
  ```

## 5. Архитектурные принципы автоматизации

1. **Принцип единого источника правды:** База данных `accounts_db.json` хранит исключительно актуальные сведения о балансе участников. История операций из структуры JSON исключена для устранения избыточности.
2. **Асинхронное логирование:** Полный хронологический след (включая действия нарушителей и системные предупреждения) вынесен в обособленный журнал учета `logs/app.log`.
3. **Отказоустойчивость:** Любое нарушение лимитов или регламента пополнения обрабатывается через механизм исключений. Программа защищена от аварийного завершения (падения) при возникновении внештатных ситуаций.
