# Система управления банковскими Кириешками

Данный проект представляет собой специализированное консольное приложение для учета, пополнения, списания и хранения баланса Кириешек на клиентских счетах. Система поддерживает персистентное NoSQL-хранение данных в JSON, сквозное логирование транзакций и полное покрытие бизнес-логики модульными параметризованными тестами.

## 1. Структура каталогов и файлов проекта

Все компоненты распределены по логическим директориям в соответствии с практикой разработки пакетов:

* `main.py` — главный исполняемый файл, запускает интерактивное меню банка для пользователя.
* `src/bank_account/account.py` — изолированная бизнес-логика банковского счета (пополнение, снятие Кириешек, валидация операций).
* `src/bank_account/exceptions.py` — кастомные классы исключений для обработки ошибок (отрицательный начальный баланс, невалидные суммы, овердрафт).
* `src/bank_account/storage.py` — модуль NoSQL базы данных для чтения и записи балансов в JSON-файл.
* `scripts/seed_accounts.py` — служебный скрипт для автоматического наполнения базы тестовыми клиентами.
* `tests/conftest.py` — конфигурационный файл pytest, содержащий глобальные фикстуры тестового окружения (`account_with_balance`, `empty_account`).
* `tests/bank_account/test_account.py` — автоматические модульные и параметризованные тесты для проверки надежности класса `BankAccount`.
* `logs/app.log` — текстовый файл, в который записывается хронология всех операций с временными метками.

## 2. Развертывание и настройка окружения

Все команды необходимо выполнять в терминале среды разработки, находясь в корневой директории проекта:

1. **Создание и активация виртуального окружения (venv):**
   * Для ОС Windows:
     ```bash
     python -m venv .venv
     .venv\Scripts\activate
     ```
   * Для ОС Linux / macOS:
     ```bash
     python -m venv .venv
     source .venv/bin/activate
     ```

2. **Установка проекта в режиме редактирования (Editable):**
   Эта процедура связывает директорию `src` с окружением, позволяя Python корректно разрешать внутренние импорты модулей из любого места:
   ```bash
   pip install -e .
   ```

3. **Установка необходимых инструментов тестирования и контроля качества:**
   ```bash
   pip install pytest pytest-cov black isort mypy
   ```

## 3. Инструкция по запуску компонентов системы

Исполняемые файлы запускаются строго из корня проекта через ключ модульного вызова `-m`:

* **Запуск интерактивного терминала оператора банка:**
  ```bash
  python -m main
  ```
  *Приложение оснащено встроенной защитой от некорректного ввода. Если пользователь вводит буквы вместо чисел, пустые строки или отрицательные значения сумм, система изолирует ошибку, выводит предупреждение и возвращает пользователя в меню.*

* **Запуск демонстрационного скрипта автоматического наполнения базы:**
  ```bash
  python -m scripts.seed_accounts
  ```
  *Инициализирует 6 тестовых аккаунтов (Alice, Bob и др.) и выводит в консоль итоговую структурированную таблицу с их балансами.*

## 4. Проведение автоматизированного тестирования (Pytest)

Проверка корректности работы классов, граничных условий и обработки ошибок осуществляется встроенным пакетом тестов. Запуск производится из корня проекта:

* **Запуск полного набора модульных тестов в подробном режиме:**
  ```bash
  python -m pytest tests/ -v
  ```
* **Запуск только критически важных проверок (Smoke-тестирование):**
  Выполняет тесты, помеченные маркером `@pytest.mark.smoke` (создание счета, позитивный депозит, строковое представление).
  ```bash
  python -m pytest -m smoke -v
  ```
* **Запуск тестов проверки исключений (Regression-тестирование):**
  Выполняет тесты с маркером `@pytest.mark.regression`, проверяющие генерацию ошибок при некорректных операциях.
  ```bash
  python -m pytest -m regression -v
  ```
* **Сфокусированный анализ покрытия бизнес-логики тестами:**
  Выводит детальный отчет о покрытии строк кода непосредственно для тестируемого класса `BankAccount`, демонстрируя результат в 100%.
  ```bash
  python -m pytest tests/ --cov=src/bank_account/account.py
  ```

## 5. Основные архитектурные решения

1. **Изоляция данных:** База данных `accounts_db.json` хранит исключительно актуальные сведения о текущем балансе Кириешек у клиентов. Архивы операций исключены из JSON для предотвращения дублирования данных.
2. **Разделение обязанностей:** Вся хронология действий (создание счетов, транзакции, системные ошибки) уходит в изолированный журнал учета `logs/app.log` с посекундными метками времени. Бизнес-логика ничего не знает о способе сохранения данных на диск.
3. **Отказоустойчивость:** Любые нарушения регламента (овердрафт по Кириешкам, неверный формат чисел) перехватываются механизмами `try-except` и кастомными исключениями. Программа защищена от аварийных падений и продолжает штатное исполнение цикла меню при возникновении внештатных ситуаций.
4. **Фикстуры и параметризация тестов:** Тестовая среда оптимизирована с помощью повторно используемых объектов в `conftest.py`. Использование декоратора `@pytest.mark.parametrize` позволяет лаконично тестировать массивы граничных значений (включая дробные доли Кириешек — 0.01) без раздувания кодовой базы тестов.
